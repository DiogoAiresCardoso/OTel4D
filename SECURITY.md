# Reporting a security issue

For a suspected vulnerability, use the repository's private “Report a vulnerability” option if available. Otherwise ask the maintainer identified in [GOVERNANCE.md](GOVERNANCE.md) for a private reporting channel. Keep sensitive details out of public issues, PRs and CI logs.

Include the affected revision and target, observable impact, relevant configuration and safe evidence with secrets and personal data removed. The maintainer coordinates triage, fixes and disclosure with the reporter. No released version or response SLA is currently advertised. Development practices are in [the security standard](docs/engineering/SECURITY_STANDARDS.md).
