# Definition of done

For each applicable item, record evidence. Explain omissions and mark unavailable checks as unverified.

- [ ] Requirements and acceptance scenarios are implemented and checked.
- [ ] Engineering principles and domain invariants hold.
- [ ] Existing components were searched and the reuse decision recorded.
- [ ] Duplicate rules and unnecessary abstractions were considered.
- [ ] Ports-and-adapters boundaries and project conventions are preserved.
- [ ] Public, wire and versioned contracts remain compatible or the break was authorized.
- [ ] Invalid inputs, failures, concurrency and cleanup were exercised where relevant.
- [ ] Security, privacy, secrets and licensing were reviewed.
- [ ] Unit and regression tests cover the changed behavior.
- [ ] Applicable integration and contract tests were executed.
- [ ] Build, static checks and applicable analysis have recorded outcomes.
- [ ] Related callers and existing functionality were considered.
- [ ] Performance and resource use were evaluated for the affected path.
- [ ] Documentation and examples match the change.
- [ ] Self-review covered scope, diff and other contributors' edits. Independent review status is recorded.
- [ ] Risks, limitations, outstanding work and skipped validation are explicit.

A handoff covers the change and affected files, reused components, decisions, architectural and functional impact, commands and results, remaining risks and any justified deviation. An item that cannot be verified remains pending.
